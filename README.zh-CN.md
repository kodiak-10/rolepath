## 产品定位

岗位描述告诉学生招聘方需要什么，却往往没有解释：从哪里开始、哪些课程值得学、完成怎样的练习才能留下有用的学习成果。

RolePath 把这些步骤放进同一个工作空间。用户可以探索示例岗位、分析真实 JD、查看有来源的课程与题目、制定符合时间预算的学习计划，并持续记录笔记和学习进度。笔记助手接受自然语言指令，围绕选中的材料进行总结、解释、比较、出题或追问。

产品面向多个岗位方向，不围绕某一家企业或某一个特殊岗位设计。当前资源库仍然有限，支持输入任意 JD 不代表已经为所有岗位配齐课程。

RolePath 区分三件事：**岗位要求什么、用户有哪些能力证据、用户记录完成了什么。** 勾选完成是一条学习记录，不是能力认证。

## 从岗位到行动

| 环节 | 用户操作 | 得到的结果 |
| --- | --- | --- |
| 探索 | 查看示例方向或带入真实岗位 | 从工作内容出发的准备方向 |
| 理解 | 粘贴或上传 JD | 保留原文依据的要求与条件 |
| 找资源 | 查看课程章节和练习来源 | 对应的学习材料及明确的资源缺口 |
| 做计划 | 填写经历、每周时间和准备周期 | 学习、复习与实践任务安排 |
| 学习 | 完成任务、记录时间并上传笔记 | 打卡、心得与学习材料 |
| 复盘 | 向笔记助手下达具体指令 | 附带原文片段的分析结果 |
| 回看 | 搜索历史并继续指定计划 | 同一账号内可延续的学习记录 |

## 产品能力

### 有原文依据的岗位分析

支持粘贴 JD，以及上传文档或图片。配置 AI 后，可抽取原文明确出现的要求并保留引用。界面区分技能要求与学历、时间等非技能条件，也允许用户引用真实原文，手动补充遗漏要求。

没有 API Key 时可以使用有限的关键词初筛，但它不等于完整语义分析，也不等于技能重要性排名。首页的三个方向用于演示，不是实时招聘信息。

### 有出处的课程与练习

根据岗位要求和已有资源元数据进行匹配；有章节信息时，指向具体章节，而不是要求用户看完整套课程。资源卡片展示已有的作者、发布时间、学习预算与核查说明。

相关性相同时可以优先 B 站，不对某个作者统一加权。练习区分原始题库、公开面经回忆和学习作业，不把回忆题包装成企业官方考试，也不把模型练习冒充真题。

当前使用有限资源目录，并非实时全网搜索。找不到课程时显示缺口，不编造链接。核查目录和出处也不代表已逐集完成质量评审。

### 受时间预算约束的学习计划

用户提供每周学习时间、准备周期以及可选的项目经历。规划器根据要求类型、原文明示重点与现有证据排序，匹配资源，并在总时间预算内安排每天的任务。

当前排期由规则完成。自述和材料中的技能提及只是证据线索，不代表已经掌握。计划会展示资源缺口和因时间限制未安排的技能；较长任务可以分配到多天。

### 可以下指令的笔记助手

用户可以选中一份或多份笔记，要求助手总结、解释概念、比较内容、生成明确标注的练习题、检查理解或提出追问。助手并非每次都执行同一种全文总结。

模型返回来源编号，程序检查编号是否存在，再附上对应原文。结构不符合要求的结果不会被作为有效分析保存。**引用结构校验不等于逐条判断模型结论正确。**

图片先识别成文字，再交给模型；当前助手不能直接理解原图。手写公式、图表和复杂排版需要人工核对。“资料问答”则用于从同一批材料中检索相关段落，回答具体问题。

### 历史记录与中英文界面

历史记录支持搜索已保存的计划、笔记和分析，并继续指定计划。打卡和学习记录随账号保存；未保存草稿、独立 JD 分析和完整对话历史不会自动全部留痕。

界面默认英文，顶部 **Language / 语言** 可切换简体中文。切换语言保留当前页面与输入，原始 JD、笔记、课程名称和引用保持原文。界面语言切换不会自动翻译全部模型输出。

## AI 与程序分别负责什么

| 责任 | 当前实现 |
| --- | --- |
| 理解岗位要求 | 大模型抽取与来源编号校验；无 API 时提供有限关键词模式 |
| 整理和解释笔记 | 根据用户指令生成有来源的分析 |
| 回答资料问题 | 检索相关片段，再按需调用模型 |
| 匹配课程与题目 | 已收录目录与相关性规则 |
| 安排学习时间 | 总预算约束下的确定性排期 |
| 保存记录和限制数据访问 | 应用存储与数据库权限策略 |
| 自动验证能力、动态重排 | 尚未实现 |

当前产品是 AI 辅助学习流程，不是能够独立判断职业适配度、验证能力或保证求职结果的全自动职业顾问。

## 技术架构

```text
Streamlit 工作空间
  ├── 中英文展示层
  ├── 邮箱验证码登录 → Supabase Auth
  ├── 岗位分析 → 关键词规则 / 用户配置的大模型
  ├── 资源目录 → 匹配 → 时间预算规划
  ├── 文档上传 → 文字提取 / OCR → 片段检索
  └── 笔记助手 → 来源编号校验 → 保存分析

数据存储
  ├── 本机个人使用：SQLite
  └── 云端多用户使用：Supabase + 行级访问策略
```

界面使用 Streamlit 与自定义 CSS；模型通过 OpenAI 兼容客户端调用支持的百炼接口。默认检索使用关键词路径，代码中也有可选 BGE / Chroma 集成，但基础依赖并不包含其全部额外包和模型文件。

PDF 使用文本提取；macOS 图片识别使用 Vision，Linux 使用 Tesseract 与中英文语言包。用户认证由 Supabase 处理。

## 数据与隐私

云端在载入个人资料前要求登录。数据库使用用户归属字段与行级访问策略；只在页面隐藏内容不能替代权限控制。新部署应使用两个独立账号验证隔离效果。

浏览器可保存最长七天的 Supabase 会话凭据，恢复时由服务端验证。无痕模式、浏览器存储限制或更换浏览器会影响登录连续性，不同设备不共享本地凭据。

AI 采用用户自备 Key 模式：

- 每位用户填写自己的百炼地址、API Key 和模型名称，调用费由该用户承担。
- Key 只保存在当前应用会话，不写入应用数据库或浏览器长期会话存储。
- 新会话可能需要重新填写 Key。
- 用户主动请求 AI 分析时，相关选中资料与上下文会发送给配置的模型服务商。

不要上传 `.env`、私钥、验证码、会话凭据、本机数据库或私人笔记到仓库。访客客户端使用 publishable/anon key 与登录权限，不使用管理员 service-role key。本项目不宣称已通过独立安全审计。

## 本机运行

本机开发曾使用 Python 3.13，请使用与依赖范围兼容的 Python 环境。

```bash
git clone https://github.com/kodiak-10/rolepath.git
cd rolepath
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

个人版记录保存在工作目录的 `.rolepath.sqlite3`，不提供云端账号隔离。需要本机 AI 时，可创建不提交到仓库的 `.env`：

```dotenv
LLM_API_KEY=your-own-api-key
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
LLM_ENABLE_THINKING=false
```

地址与模型需在你自己的服务商账号中可用。macOS 图片识别需要 Swift / Vision 运行环境；Linux 需安装 `packages.txt` 中的系统 OCR 依赖。

## 部署说明

1. 为自己的部署创建 Supabase 项目，并执行 [`deploy/supabase.sql`](deploy/supabase.sql)。
2. 将 `deploy/public_config.json` 改为该项目的 URL 与 publishable/anon key，不复用其他部署的后端。
3. 配置邮件发送服务、站点 URL 与邮箱验证码模板，模板中包含数字验证码 `{{ .Token }}`。
4. 在 Streamlit Community Cloud 部署，入口选择 **`cloud_app.py`**，保留根目录中的依赖文件。
5. 上线前验证邮件送达、登录、退出、会话恢复、双账号隔离以及记录保存。
6. 用户通过 **账户与设置 → AI 服务设置** 连接自己的模型。本机 `.env` 不会自动作为全站 AI 服务。

免费托管不代表模型调用免费，也不等于生产环境可用性保证。

## 当前限制与后续方向

资源库仍需扩展并持续编辑核查；OCR 和大模型解释可能有误；课程选择与计划尚未形成自动适应学习情况的模型策略。打卡不等于能力测验，自动批改代码、作品与答案尚未实现。

笔记分析有输入与对话长度限制，大批材料需分批处理。英文界面不会自动翻译中文课程和所有模型输出；手机与内置浏览器仍需针对实际部署验证。

后续方向是提高资源质量、完善基于证据的反馈与学习连续性，而不是提前宣称完成全自动职业规划。
